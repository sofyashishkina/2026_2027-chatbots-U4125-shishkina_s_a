# Описание

В этой лабораторной работе будет реализована интеграция бота с реальными данными - файлами, API, базами данных.

# Цель работы

Научиться подключать бота к внешним источникам данных и работать с ними через LLM-генерацию кода.

# Ход работы

## Шаг 1: Выбор типа интеграции

В прошлой версии бота (для Лабораторной №1) уже была реализована работа с файлами (отображение карточек мастер-классов) и использование БД SQLite.

Промпт (`lab1/prompt.txt`) изначально создавался подробным, поэтому ChatGPT в него сразу включил и отображение карточек мастер-классов и хранение данных пользователей в БД SQLite для централизованной рассылки.

## Шаг 2: Подготовка данных

Файлы - фото для отображения в боте лежат в папке `lab1/assets`:
- `catalog` - папка с карточками мастер классов;
- `event` - папка с карточками афиши;
- `price` - папка с прайс листами (оставлена пустой).

Структура:

```
assets/
    catalog/
        01.jpg
        02.jpg
        03.jpg
        ...
    price/
        price_1.jpg
        price_2.jpg
    events/
        01.jpg
        02.jpg
        ...
```

БД SQLite для централизованной отправки уведомлений пользователям состоит из 1 таблицы `users`:

- `id` - уникальный ID пользователя в БД;
- `telegram_id` - ID пользоваеля внутри Telegram;
- `username` - ник пользоваеля внутри Telegram;
- `first_name` - имя пользоваеля внутри Telegram;
- `last_name` - фамилия пользоваеля внутри Telegram;
- `first_seen_at` - время, когда пользователь первый раз использовал бота;
- `last_seen_at` - время, когда пользователь последний раз использовал бота;
- `is_active` - пользователь активен или нет;
- `blocked_at` - это дата и время, когда бот обнаружил, что пользователь заблокировал его или больше не может получать сообщения.

## Шаг 3: Составление промпта для LLM

Интеграция с данными уже была реализована в версии бота для Лабораторной №1, поэтому ниже приведен фрагмент промпта, составленного ChatGPT, в котором описаны эти интеграции:

```
--------------------------------------------------
КАКИЕ ДАННЫЕ ХРАНИТЬ
--------------------------------------------------

Использовать SQLite.

Создать таблицу:

users

Поля:

id
telegram_id
username
first_name
last_name
first_seen_at
last_seen_at
is_active
blocked_at

telegram_id должен быть UNIQUE.

При /start:

Если пользователя нет:
- добавить новую запись;
- установить is_active = 1;
- записать first_seen_at;
- записать last_seen_at.

Если пользователь уже есть:
- обновить last_seen_at;
- установить is_active = 1.

Не создавать несколько записей для одного telegram_id.

--------------------------------------------------
РАБОТА С ИЗОБРАЖЕНИЯМИ
--------------------------------------------------

Использовать следующую структуру:

assets/
    catalog/
        01.jpg
        02.jpg
        03.jpg
        ...
    price/
        price_1.jpg
        price_2.jpg
    events/
        01.jpg
        02.jpg
        ...

Использовать pathlib.

Для каталога и афиши:
- автоматически читать содержимое папки;
- сортировать изображения;
- автоматически разбивать по максимум 10 файлов в MediaGroup.

Если папка отсутствует, создать понятную обработку ошибки.

Если одного изображения нет или оно повреждено, приложение не должно полностью завершаться.
```
